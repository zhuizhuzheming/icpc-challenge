/* 
 * ==============================================================================
 * 多智能体 Stackelberg 博弈增强型 XR 调度系统
 * —— 支持双用户联盟投标、社会福利项
 * ==============================================================================
 *
 * 本调度器采用“基于紧迫度驱动的多智能体竞标 + 功率精细优化”两阶段策略，
 * 在满足 5G+ 网络资源约束的前提下最大化成功传输的 XR 帧数量。
 *
 * 【核心流程】
 * 1. **帧状态跟踪**：
 *    - 每个帧维护已传输比特数、总耗电、完成状态等；
 *    - 按 TTI 维护活跃帧列表，仅对未完成且在时间窗内的帧调度。
 *
 * 2. **用户紧迫度计算（calculate_urgency）**：
 *    - 结合剩余比特量、截止时间临近程度（指数加权）、用户公平性（饥饿惩罚）；
 *    - 用于衡量该用户当前最紧急帧的调度优先级。
 *
 * 3. **多智能体竞标机制（BiddingAgent）**：
 *    - 每个用户拥有一个基于粒子群的轻量级强化学习代理；
 *    - 代理通过 urgency 计算“出价”，并引入社会福利项（鼓励协作）；
 *    - 使用邻域奖励传播与权重更新机制实现在线策略演化。
 *
 * 4. **RBG-TTI 级调度决策（multi_agent_schedule_tti）**：
 *    - 对每个 (r, k, t) 资源单元，收集所有可行单用户/双用户候选；
 *    - 双用户模式仅考虑紧迫度最高的两个用户，尝试联合调度以提升频谱效率；
 *    - 依据智能体出价选择胜出者（单人或联盟）。
 *
 * 5. **功率分配优化**：
 *    - 单用户：使用模拟退火（SA）搜索最优功率，平衡速率增益与功耗惩罚；
 *    - 双用户：网格搜索联合功率分配，最大化归一化速率和；
 *    - 所有分配严格遵守 per-RBG 功率上限（≤4）及 per-cell 总功率预算（R）。
 *
 * 6. **跨小区干扰建模与更新**：
 *    - 实时维护 cross_cell_power，反映其他小区在同 RBG 上的发射功率；
 *    - SINR 计算包含同小区多用户干扰（通过 d[m][r][k][n] 衰减因子）与跨小区干扰。
 *
 * 7. **反馈与代理学习**：
 *    - 每帧结束时（t == t1,j），根据是否成功传输、总耗电、他人成功情况，
 *      生成 surplus 信号用于更新对应用户的 bidding agent 权重；
 *    - 引入 SOCIAL_BONUS 鼓励“利他”行为，提升系统整体吞吐。
 *
 * 【设计亮点】
 * - 融合博弈论（Stackelberg 竞标）、启发式紧迫度、轻量强化学习与局部优化；
 * - 支持动态联盟（双用户共享 RBG），提升高频谱效率场景下的性能；
 * - 全流程满足问题约束（功率、时间窗、输出格式），避免非法解。
 */
